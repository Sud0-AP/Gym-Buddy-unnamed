Firmware Screen Refactoring Guide

Clean architecture for ESP32 display rendering — one file per screen, centralized assets, scalable for Phase 1 and beyond

📋 Refactoring Summary

Problem: All screen rendering code lives in one 416-line lopaka_generated.cpp file, making it hard to manage and difficult for coding agents to navigate.

Solution: Split into one file per screen + centralized asset library + shared UI primitives. Clean separation, agent-friendly, scales to 9+ screens.

Target Structure

Hardware/Firmware/src/display/ ├── display_task.h // Display task interface (unchanged) ├── display_task.cpp // Routing logic (minimal edits) ├── display_events.h // Event types (unchanged) ├── assets.h // All Lopaka bitmaps + constants ├── assets.cpp // Asset definitions ├── ui_primitives.h // Shared rendering functions ├── ui_primitives.cpp // Top bar, scrollbar, etc. ├── screens.h // All screen function declarations └── screens/ // One file per screen ├── main_menu.cpp ├── settings_main.cpp ├── settings_display.cpp └── settings_brightness.cpp

Step-by-Step Implementation

1Create Directory Structure
mkdir -p Hardware/Firmware/src/display/screens
2Rename lopaka_generated.cpp → assets.cpp

This file becomes the central asset library. Keep only the asset definitions (bitmaps, constants, color defines), remove all rendering functions.

mv Hardware/Firmware/src/display/lopaka_generated.cpp \
   Hardware/Firmware/src/display/assets.cpp

Edit assets.cpp: Delete all function implementations (draw_topbar(), draw_main_menu_full(), etc.), keep only:

  • All PROGMEM bitmap arrays
  • Color constants (COLOR_BG, COLOR_ACCENT, etc.)
  • Layout constants (ITEM_Y_POSITIONS, TEXT_Y_POSITIONS, etc.)
  • Label arrays (MENU_LABELS, SETTINGS_MAIN_LABELS, etc.)

⚠️ Managing Large Assets

As you add more screens, assets.cpp will grow (potentially 1000+ lines). Keep it manageable:

  • Use clear section comments: // ===== SCREEN NAME ASSETS =====
  • Group related assets together (all brightness screen bitmaps in one block)
  • Consider splitting into assets_common.cpp (top bar, scrollbar) + per-screen asset files if it exceeds ~1500 lines
  • The assets.h header stays clean — only declarations, no bloat

5Create ui_primitives.cpp

Extract shared rendering functions from the old lopaka_generated.cpp.

#include "ui_primitives.h"
#include "assets.h"

void draw_topbar() {
    // Layer 1: Margins/background frame drawn FIRST
    tft.pushImage(0, 0, 320, 21, image_topbar_margins_pixels);

    // Battery level fill (75% default for Phase 1)
    tft.fillRect(296, 5, 12, 9, COLOR_ACCENT);

    // Battery case outline
    tft.drawBitmap(286, 2, image_topbar_battery_case_bits, 24, 16, COLOR_GREY_TRACK);

    // Time text
    tft.setTextColor(COLOR_ACCENT);
    tft.setTextSize(1);
    tft.drawString("12:23 PM", 75, 6);

    // Back icon
    tft.drawBitmap(10, 5, image_topbar_back_bits, 10, 8, COLOR_ACCENT);

    // Info icon
    tft.drawBitmap(45, 5, image_topbar_info_bits, 7, 8, COLOR_ACCENT);

    // Day & date text
    tft.drawString("Monday: 14th May", 140, 6);

    // Network connected icon
    tft.drawBitmap(252, 3, image_topbar_network_connected_bits, 15, 14, COLOR_ACCENT_NET);
}

void draw_scrollbar_thumb(uint8_t sel) {
    uint16_t ty = THUMB_Y_POSITIONS[sel];
    tft.fillRect(303, ty, 9, 15, COLOR_ACCENT);

    if (sel == 0) {
        tft.drawLine(304, 62, 310, 62, COLOR_GREY_INNER);
        tft.drawLine(304, 65, 310, 65, COLOR_GREY_INNER);
        tft.drawLine(304, 68, 310, 68, COLOR_GREY_INNER);
        tft.drawLine(304, 71, 310, 71, COLOR_GREY_INNER);
    } else if (sel == 1) {
        tft.drawBitmap(304, 109, image_Layer_23_bits, 7, 10, COLOR_GREY_TRACK);
    } else {
        tft.drawLine(304, 170, 310, 170, COLOR_GREY_INNER);
        tft.drawLine(304, 173, 310, 173, COLOR_GREY_INNER);
        tft.drawLine(304, 176, 310, 176, COLOR_GREY_INNER);
        tft.drawLine(304, 179, 310, 179, COLOR_GREY_INNER);
    }
}

7Create Screen Files

Extract each screen's rendering code into its own file in screens/.

screens/main_menu.cpp

#include "../screens.h"
#include "../assets.h"
#include "../ui_primitives.h"
#include <TFT_eSPI.h>

extern TFT_eSPI tft;

static void draw_menu_item(uint8_t index, bool is_selected) {
    uint16_t pill_y = ITEM_Y_POSITIONS[index];
    uint16_t icon_y = ICON_Y_POSITIONS[index];
    uint16_t text_y = TEXT_Y_POSITIONS[index];

    if (is_selected) {
        tft.drawBitmap(20, pill_y, image_menu_selection_pill_bits, 260, 72, COLOR_ACCENT);
        tft.setTextColor(COLOR_TEXT_SEL);
    } else {
        tft.fillRect(20, pill_y, 260, 72, COLOR_BG);
        tft.setTextColor(COLOR_TEXT_UNSEL);
    }

    // Animation icon placeholder (static frame 0)
    tft.drawRect(27, icon_y, 48, 48, COLOR_GREY_INNER);

    // Item label
    tft.setTextSize(2);
    tft.drawString(MENU_LABELS[index], 110, text_y);
}

void draw_main_menu_full(uint8_t selection_index) {
    if (selection_index > 2) selection_index = 0;

    tft.fillScreen(COLOR_BG);
    draw_topbar();

    // Scrollbar track
    tft.fillRect(302, 32, 12, 194, COLOR_GREY_TRACK);
    tft.fillRect(304, 34, 7, 190, COLOR_GREY_INNER);
    tft.drawBitmap(301, 24, image_scrollbar_arrow_up_large, 14, 8, COLOR_GREY_TRACK);
    tft.drawBitmap(304, 30, image_scrollbar_arrow_up_small, 7, 4, COLOR_GREY_INNER);
    tft.drawBitmap(301, 226, image_scrollbar_arrow_dn_large, 14, 8, COLOR_GREY_TRACK);
    tft.drawBitmap(304, 224, image_scrollbar_arrow_dn_small, 7, 4, COLOR_GREY_INNER);

    // Draw all 3 items
    for (uint8_t i = 0; i < 3; i++) {
        draw_menu_item(i, i == selection_index);
    }

    draw_scrollbar_thumb(selection_index);
}

void draw_main_menu_update_selection(uint8_t old_index, uint8_t new_index) {
    if (old_index == new_index) return;
    if (old_index > 2) old_index = 0;
    if (new_index > 2) new_index = 0;

    draw_menu_item(old_index, false);
    draw_menu_item(new_index, true);

    uint16_t old_ty = THUMB_Y_POSITIONS[old_index];
    tft.fillRect(303, old_ty, 9, 15, COLOR_GREY_INNER);
    draw_scrollbar_thumb(new_index);
}

Create similar files for the other 3 screens (settings_main.cpp, settings_display.cpp, settings_brightness.cpp) by extracting their respective functions from the old lopaka_generated.cpp.

8Update display_task.cpp

Replace the old lopaka_generated.h include with the new headers.

// OLD:
// #include "lopaka_generated.h"

// NEW:
#include "screens.h"
#include "ui_primitives.h"

// All draw_* function calls remain unchanged!

The routing logic in display_task.cpp stays exactly the same — you're just swapping where the functions are declared.

9Update PlatformIO Build

PlatformIO automatically discovers .cpp files in src/ and its subdirectories, so the new structure should compile without platformio.ini changes. Verify:

cd Hardware/Firmware
pio run

If you see linker errors about missing symbols, check that:

  • All .cpp files are in src/display/ or src/display/screens/
  • extern declarations in assets.h match the actual definitions in assets.cpp
  • screens.h declares all functions implemented in the screen .cpp files
10Delete Old File
rm Hardware/Firmware/src/display/lopaka_generated.h

The old header is no longer needed — screens.h + assets.h + ui_primitives.h replace it.

Adding New Screens

Once the refactor is complete, adding a new screen becomes a 4-step process:

  1. Export from Lopaka: Get the .txt + .png for the new screen
  2. Append assets to assets.cpp: Copy bitmap arrays + constants, add extern declarations to assets.h
  3. Create screens/new_screen.cpp: Implement draw_new_screen_full() + any update functions
  4. Declare in screens.h: Add function prototypes so display_task.cpp can call them
🎯 Benefits
  • Agent-friendly: "Modify the brightness screen" → agent opens settings_brightness.cpp directly
  • Scales cleanly: 9 Phase 1 screens = 9 files, each ~60-150 lines
  • Clear ownership: Each screen file owns its rendering logic, no hunting through 1000+ line monoliths
  • Build-time validation: Missing asset? Linker error points to exact extern declaration
  • Easy diffing: Git history shows per-screen changes, not "modified lopaka_generated.cpp" for every change

Common Pitfalls

⚠️ Watch Out For
  • Missing extern in assets.h: If a screen file references a bitmap but you forgot to declare it in assets.h, you'll get a linker error. Add the extern declaration.
  • Wrong extern TFT_eSPI tft;: Each screen .cpp file needs extern TFT_eSPI tft; at the top to access the global TFT instance (defined in display_task.cpp).
  • Forgetting to update screens.h: If you add a new screen function but forget to declare it in screens.h, display_task.cpp can't see it.
  • Asset name collisions: If two screens export bitmaps with the same variable name (e.g., both have image_Layer_1_bits), rename one to be screen-specific (e.g., image_brightness_layer_1_bits).
