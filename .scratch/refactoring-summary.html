New Architecture

1. Common Assets (assets_common.cpp/h)

Shared elements used across multiple screens:

  • Color constants: COLOR_BG, COLOR_ACCENT, COLOR_GREY_TRACK, etc.
  • Layout constants: ITEM_Y_POSITIONS[3], TEXT_Y_POSITIONS[3], THUMB_Y_POSITIONS[3]
  • Top bar assets: Battery, WiFi, back/info icons, margin graphic
  • Scrollbar assets: Arrows (up/down, large/small), center marker
  • Selection pills: Main menu pill, settings pill

Large arrays extracted to .inc files: lopaka_topbar_margins.inc (47KB), lopaka_menu_pill.inc (12KB), lopaka_settings_pill.inc (13KB) — keeps assets_common.cpp readable.

2. UI Primitives (ui_primitives.cpp/h)

Reusable rendering functions called by multiple screens:

  • draw_topbar() — Battery, WiFi, time, date, back/info icons
  • draw_scrollbar_thumb(uint8_t selection_index) — Animated thumb with correct decoration per position

Prevents code duplication across the 4 screens that share these elements.

3. Screen Files (screens/*.cpp)

One file per screen, each fully self-contained:

File Lines What It Owns
main_menu.cpp ~80 Main Menu rendering + 3 menu labels + pill drawing helper
settings_main.cpp ~70 Settings—Main rendering + labels (Display, Hype & Rest, Pairing)
settings_display.cpp ~70 Settings—Display rendering + labels (Brightness, Theme, Home screen)
settings_brightness.cpp ~140 Brightness screen + all brightness-specific assets (slider, buttons, sample icons) — self-contained!

Key insight: settings_brightness.cpp embeds its 11 screen-specific bitmap arrays directly in the file, demonstrating the "self-contained screen-specific assets" pattern. Future screens follow this model.

4. Unified Interface (screens.h)

Single header declaring all screen rendering functions:

void draw_main_menu_full(uint8_t selection_index);
void draw_main_menu_update_selection(uint8_t old_index, uint8_t new_index);

void draw_settings_main(uint8_t selection_index);
void draw_settings_main_update_selection(uint8_t old_index, uint8_t new_index);

void draw_settings_display(uint8_t selection_index);
void draw_settings_display_update_selection(uint8_t old_index, uint8_t new_index);

void draw_settings_brightness(uint8_t brightness_value);
void draw_settings_brightness_update_value(uint8_t old_value, uint8_t new_value);

display_task.cpp includes only screens.h + ui_primitives.h — clean, single point of entry.

Scalability

Phase 1 has 9 total screens. The new structure scales cleanly:

Screen Count Old Structure (Monolithic) New Structure (Modular)
4 screens (current) 416 lines in one file 4 files @ ~60-140 lines each
9 screens (Phase 1 complete) ~900+ lines in one file 🔥 9 files @ ~60-150 lines each ✓
15+ screens (future phases) 1500+ lines, unmanageable 15 files, assets split by screen

Asset organization: Screen-specific assets live in their screen file (brightness slider in settings_brightness.cpp). Common assets stay in assets_common.cpp. Large arrays extracted to .inc files keep source files readable.

Adding Future Screens

The 4-step process for each new screen:

  1. Export from Lopaka: Get .txt + .png for the new screen
  2. Create screen file: screens/new_screen.cpp with rendering functions + screen-specific assets
  3. Add to screens.h: Declare draw_new_screen_full() and any update functions
  4. Wire in display task: display_task.cpp routing calls the new function

Common assets (top bar, scrollbar) already exist — new screens include assets_common.h and call draw_topbar() directly.
